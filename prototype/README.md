# 生产级 ETL-Agent 数据集成平台 · 高保真原型

依据 **PRD v1.2 §7**（关键页面原型说明）与 **SPEC v1.1** 生成的控制台原型。

## 产出物

| 文件 | 用途 |
|------|------|
| `prototype.pen` | **设计源文件**（pen.dev 开放 JSON 格式，版本 `2.21`）。用 VS Code 的 pen.dev 扩展打开可编辑 |
| `prototype-preview.html` | **浏览器直接打开**（无需安装 pen.dev）。带 25% / 42% / 65% / 100% 缩放切换 |
| `overview.png` | 5 个页面总览截图（一屏看全） |
| `detail-*.png` | 单页放大截图（`overview` / `connections` / `studio` / `operations` / `governance`） |
| `penlib.py` | 生成工具库：设计令牌 + 复合组件（卡片 / 表格 / 标签 / 按钮 / 指标卡 / 进度条） |
| `generate_prototype.py` | 页面装配脚本 → 输出 `.pen`，并做结构校验 |
| `render_preview.py` | `.pen → HTML` 渲染器（自研，无外部依赖） |
| `detail-page-*.html` | 单页放大预览（由渲染器临时生成） |

## 五个页面（对应 PRD §7.1 ~ §7.5）

| # | 页面 | 核心任务 | 主要角色 |
|---|------|---------|---------|
| 01 | **总览工作台** | 查看项目概况并进入目标垂直切片。**不提供直接提交作业入口** | 全部项目成员 |
| 02 | **数据连接** | 登记连接、连通性测试、Profile 探查、脱敏样本、文件资产与 Secret 生命周期 | 数据工程师、管理员 |
| 03 | **Pipeline Studio** | 描述需求 → LangGraph 澄清 → 生成 EtlPlan/HOCON → DAG 与 Diff 审查 → 门禁 → 冻结 → 提交审批 → 调度配置 | 数据工程师、数据审批人 |
| 04 | **运行中心** | 准备单与双审批槽、执行监控、质量分流、可解释诊断、受管回滚与治理区 | 操作员、审批人、审计员 |
| 05 | **安全治理** | Benchmark 用例集（20 条）、六项指标大盘、门禁结论与报告输出、改进候选审查 | 安全审批人、审计员 |

## 原型中刻意体现的治理约束

这些不是装饰，是把 PRD/SPEC 的硬规则画进界面，便于评审时逐条核对：

- **总览页**不出现「直接提交作业」按钮（对应 PRD §7.1「明确不做」）
- **准备单面板**上申请人（王五）的审批按钮**置灰并标注「不可自批」**（SOD-01）
- 准备单展示**输入指纹 / Artifact 摘要 / 预算配额 / 影响范围 / 回滚方案**，而非只有任务名（FR-51）
- **数据连接页**凭据只显示 `vault://…` 引用，**不提供明文查看入口**（G-07）
- **Profile 视图**样本一律脱敏（`a***@ex***.com`、`138****1234`），并标注「原文不落盘」
- **Studio** 门禁把「真实引擎检查」列为必过项之一（FR-35）；标注「修改需求将创建 V+1，不覆盖本版本」（FR-39）
- **运行中心**显示 `错误拒绝率 1.8% / 阈值 50%`、`输出放大比 1.1× / 阈值 2.0×`（FR-76）
- **安全治理页**列出 **20 条**用例，其中 **4 条是针对新增数据源（REST API / 对象存储 / ClickHouse）的攻击面**（SPEC T-63）；并标注「任一 P0/P1 漏拦即整体失败」
- 改进候选区标注「`PROMOTION_APPROVED` 只是授权，不等于热更新」（FR-91）
- 侧栏底部展示**策略包版本**与**运行环境**（策略决策可追溯，FR-49）

## 预览方式

```bash
# 方式一：直接打开（推荐）
start prototype-preview.html

# 方式二：重新生成后预览
python generate_prototype.py   # 生成 .pen（含结构校验）
python render_preview.py       # 生成 HTML
```

## 修改设计

改 `generate_prototype.py`（页面内容）或 `penlib.py`（设计令牌、组件），然后重跑两个脚本即可。
**不要手改 `.pen`** —— 它由脚本生成，手工改会在下次重跑时被覆盖。

## 设计约定

| 项 | 约定 |
|----|------|
| 画板尺寸 | **1440 × 920**，3 列 × 2 行网格（列距 1560 / 行距 1020） |
| 配色 | 浅色主题：底 `#F4F6F9`、卡片 `#FFFFFF`、边框 `#E3E8EF`、主色 `#2563EB`；成功 `#059669` / 警示 `#B45309` / 危险 `#DC2626` / 紫 `#7C3AED`（用于安全维度） |
| `lineHeight` | 是 **fontSize 的倍数**（`1.5` = 150%），不是 px —— 这是 `.pen` schema 的约定 |
| 图标 | 渲染为**图标槽位占位**（线框风格），保留 `data-icon` 属性标注 lucide 图标名，便于替换为真实图标 |
| 窄栏内不用表格 | 三栏布局的窄栏里改用**竖排行**展示类型映射，避免列宽挤压截断 |

## 已知边界

- 这是**原型**，非可运行前端。真实实现在 `SPEC.md §10` 的 **T-47 ~ T-53**（M7 阶段）。
- 原型只覆盖 PRD §7 的五个主页面，未画弹窗、抽屉、空状态与错误态。
- 数据为演示用**示例数据**，不代表真实环境数值（PRD 已注明「验收应检查状态含义与后端事实是否一致，而非数字相同」）。
